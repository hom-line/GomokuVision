# GomokuVision V0.3.1 — WPF 視窗排版實機驗收

## 為什麼修正

使用者 V0.3.0 Windows 截圖可見：底部的「開啟結果資料夾／取消分析／開始辨識與預測」文字被擠壓。舊版 XAML 將底部固定為 `RowDefinition Height="64"`，又在同一列放入狀態、進度條與按鈕。縮放、高 DPI、較長的繁體中文標籤可能造成內容無法完整顯示。本次修改不涉及辨識演算法。

## A. 只測 WPF 編譯／開啟（完全不重跑影片）

1. 全新目錄解壓，執行 `scripts\Verify-WPF-Build-Windows.bat`，須顯示 `WPF_BUILD_PASS`。
2. 雙擊 `Launch-Desktop-Windows.bat`，真正的 WPF 主視窗應開啟，而不是備用 HTML Viewer。
3. 底部狀態文字應與進度條、三個操作按鈕分成上下兩列，不得有文字被擠到按鈕之外。
4. 「開啟結果資料夾」、「取消分析」、「開始辨識與預測」的完整文字應清楚可見；停用的取消按鈕可以呈灰色，但文字不可遭裁切。
5. 載入預設歷史 41 手結果後，底部狀態文字可以顯示省略號；移動滑鼠到狀態文字應顯示全文提示。

## B. 解析度與 DPI（建議逐項做，不必更改辨識數據）

- 在 100% 缩放、正常大小視窗：三欄與底部按鈕均完整顯示。
- 將視窗寬度縮窄到約 900 DIP：中間內容應出現水平捲軸；底部操作列依然維持可見。
- 將視窗高度縮小到約 550 DIP：中間內容應出現垂直捲軸；底部操作列不應超出工作列或畫面。
- 如果方便，切換 Windows 顯示 125% 或 150%：底部按鈕文字仍應完整；不必把畫面強制改成全螢幕。
- 在較小工作區首次啟動：視窗應自動縮到工作列上方且保留操作列。多螢幕情況仍需要個別人工確認。

## C. 回歸檢查

- 歷史 41 手棋譜不會重新辨識；使用「上一手」「下一手」、棋譜滑桿能正常重繪右側棋盤。
- 切換繁體中文／English，底部按鈕不裁切；影片未配對的提醒保留。
- 使用「載入影片預覽」讀取 `demo/demo.mp4` 可選做；它是自製合成影片，不能冒充歷史 41 手原始影片。
- 若需要演算法驗收，另執行 `Quick-Engine-Gate-Windows.bat`：僅使用短合成影片；此項不是版面修正的前提。

## 證據與限制

- 本環境已完成 39/39 Python/來源合約測試，包含新增的 6 項 XAML 版面契約。
- **這不是 Windows 螢幕截圖視覺驗收；本版 WPF 編譯及實際 DPI 呈現仍須 Windows 複驗。**
- 既有 V0.2.6 雙引擎 11/11 合成驗收為先前使用者提供的證據，不視為本版 GUI 新功能已自動通過。
