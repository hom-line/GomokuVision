# V0.3 GUI 影片與棋譜同步驗收（Windows）

## 驗收邊界

- V0.2.6 已於使用者 Windows 10 / .NET 10.0.403 通過 11/11 快速驗收；此證據屬於舊版，不代表 V0.3 GUI 已自動通過。
- V0.3 新增視覺重播與影格定位；此處的 Python 測試與 XAML 靜態檢查不能取代 Windows WPF 真實互動驗收。
- 歷史 961 幀影片與原始第三方影片素材**不隨專案散布**。不用為了測 GUI 重新處理歷史影片。

## A. 離線棋譜（不需影片）

1. 雙擊 `Launch-Desktop-Windows.bat`，確定開啟 WPF，而不是 HTML Viewer。
2. 檢查歷史棋譜顯示 41/41；右側為棋盤，畫有最後一步的藍色圈及終局勝利連線。
3. 按「上一手」→ 棋盤少一顆；按「下一手」→ 恢復。
4. 拖動「棋譜」滑桿到 0，棋盤應空；拖到 20，恰有 20 顆棋；拖到 41 恢復終局。
5. 點擊落子清單第 15 列，棋盤應只畫 15 手，藍圈位於第 15 手。
6. 按「播放棋譜」，從目前手數逐手自動播放；再按一次暫停。
7. 切換 English / 繁體中文，按鈕文字應變更、結果不應被清空。

## B. 影片預覽（僅套件自製示範影片）

1. 輸入 `demo/demo.mp4`，按「載入影片預覽」。
2. 顯示影格計數 / FPS 換算秒數；拖曳影格滑桿到末端，畫面會改變。
3. 按「播放影片／暫停影片」測試預覽。
4. **注意：** 預設歷史 41 手 CSV 不是 `demo.mp4` 的結果，預覽頁必須顯示「未配對」，不得將其影格當成歷史棋譜影格。
5. 如果要測真正同步，執行一次短合成影片分析，再載入對應的 `summary.json` / `moves.csv`，或直接使用 WPF 開啟該段合成影片分析結果；只有來源影片路徑與摘要一致時，選取棋步才應自動跳到對應影格。

## C. 校準預覽

1. 按「從影片手動點選四角校準」。
2. 點外圈交叉點左上、右上、左下、右下，應出現 15×15 網格疊加。
3. 「撤銷上一點」後，網格消失，可以重新選取最後一點。
4. 在 4/4 完成時另存 CSV，檢查其 225 筆座標。

## D. 一鍵自動化

雙擊 `Quick-Engine-Gate-Windows.bat`。此腳本只跑自製合成影片。

- 既有 Python / C# 單元、戰術、9 手棋、勝方及棋譜一致性仍需 PASS。
- 新增描述性效能報告：`%LOCALAPPDATA%\GomokuVision\Gates\synthetic-<時間>\engine-comparison.json` 與 CSV。
- WPF Release 建置 PASS，尚不代表 GUI 人工操作 PASS。

## 必須保留的限制

- 歷史 CSV 41/41 與舊系統輸出吻合，不是獨立人工標註的準確率。
- 兩個引擎的合成影片耗時只供現場描述，不作不同硬體的公平 benchmark。
- MATLAB 歷史原始碼保留，尚未有等價的三語言一鍵演算法驗收。
