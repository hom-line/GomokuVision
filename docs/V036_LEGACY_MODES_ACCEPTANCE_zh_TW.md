# V0.3.6 原版 ROI／綠框重建 — Windows GUI 驗收

## 範圍與定義

- ROI 模式 **黑白分離**：各棋色需獨立通過亮度候選預篩，然後執行該色模板 NCC。
- ROI 模式 **共用**：同一候選 ROI 只要符合任一棋色亮度特徵，便執行黑、白雙模板 NCC（最終仍以各自閾值及相對分數決定）。
- 畫面模式 **純辨識**：綠框代表棋譜中的棋子，最新落子可有藍色強調圈；勝利時紅線。
- 畫面模式 **辨識＋預測**：加上綠色黑方／青色白方的*候選推薦圈*，不得把推薦視為實際落子。

## 低成本預覽，不重跑辨識

在 WPF 載入 `demo/full_game/full_game_961.mp4` 與配對棋譜，選取第 1、25、43、493、949、961 幀。移動影片滑桿與逐手滑桿，左右應同步，綠框不應出現在尚未落子的格點。第 949 幀有 41 子，最後 961 幀仍有最後落子與勝利線。將 WPF 模式切換成純辨識時不應看到候選圈；切成預測模式，未完局時可見候選圈。輸入檔未配對應禁用棋譜同步，而非套用錯誤框。

## 原生引擎驗收

執行 `scripts/Run-Legacy-Modes-Windows.bat`：產生 Python 與 C# 在 2 種 ROI × 2 種畫面模式上的 8 組短片分析結果，分別以既知 9 手正解驗證及跨語言比較，不分析私人 961 幀原始攝影影片。若有 MATLAB，額外傳入 `-IncludeMatlab`，再以 MATLAB 原生程式產生 4 組並跟 Python 比對。結果存 `%LOCALAPPDATA%\GomokuVision\Gates\legacy-modes-*`，只在最後全部通過時顯示 `V036_LEGACY_MODES_PASS`。

若要完成新版本**完整 41 手的三引擎實測**，每個引擎以獨立資料夾重跑 `demo/full_game/full_game_961.mp4`，檢查棋色與落點 41/41、三引擎的 `roi_mode`、`overlay_mode`、`moves.csv`、`summary.json` 與進度圖片。共用 ROI 的匹配嘗試數可能更多，不應假設一定更快。
