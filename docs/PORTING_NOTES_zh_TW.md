# 移植差異與驗收紀錄

## 來源
- MATLAB 2025 課程專題原始碼，以 `matlab/legacy/` 保留，沒有修改。
- Python/C# 是針對功能重新實作，不是 1:1 語句翻譯。
- `Gemini_Prediction` 是歷史檔名；程式沒有 Gemini API 或訓練模型，預測是啟發式評分。

## 重要語義
- 棋盤內部：`[row][col]`，0 起算，`0=空、1=黑、2=白`。
- 給使用者的落子文字：欄 A~O + 列 1~15，例如 `H8`。
- 原 MATLAB 的 `checkerboard_points.csv` 標籤依序 A1, B1, ..., O1, A2...，**字母對應 row，數字對應 col**，與一般棋譜命名剛好不同。因此移植版需先轉置語義，不能以標籤直接取格子。
- 範例 `H9` 的原 CSV 是 row H(8) / col 9，但介面列印 `I8`；解析器已有專門轉換。
- `--sample-every` 依「原始影格序號」取樣；`--full-scan-every` 依「已分析影格次數」週期性全盤掃描，兩者不相互干擾。
- 局部掃描會搜尋黑白最近一次落子的鄰域聯集，不使用預測第一名作為唯一搜尋點；每隔指定次數回到全盤。
- 新程式中心亮度做黑白候選預篩，NCC 分數才作為驗證；場景與光照不同需要重校準閾值，不能保證泛化。
- 輸出每處理影格寫一次，輸出 FPS = 原 FPS / 取樣間隔，避免跳幀後影片快轉。
- Python/C# 採用**相同規則重新整理**的啟發式分數：連續子數、開放端數、中心、密度與分階段攻守比例；不等同 MATLAB 既有分數，也非 Minimax。

## 已知差異
1. MATLAB 歷史 GUI 使用 `figure` 與 `uitable`；V0.2 新增 Windows C# WPF 三欄視窗，可從 GUI 切換 Python／C# 引擎，顯示棋譜、預覽、四角校準與安全取消。WPF 原始碼尚待 Windows 實機編譯及 GUI 驗收。
2. MATLAB 會保留與修正每個棋子在畫面中的模板中心；新版本為求可重現，畫框使用經過校準的交叉點，不額外以 NCC 調整每顆已確認棋子中心。
3. Python/C# 影片解碼後細微像素差、浮點與取整方式可能導致邊界分數不同；需用實際 `compare_runs.py` 確認完整一致性。
4. 現有檔案只含先前估算出的校準點，沒有自動從影片找到角點。`make_demo.py` 與 Calibration 類別提供四角**人工提供**後的雙線性座標生成，不應稱「全自動校準」。
5. 兩個移植版本無 TensorFlow/YOLO、無 Gemini API，也沒有真正棋局樹搜尋。

## 已實測
- Python 核心測試與合成影片：成功辨識 9/9 合成落子（該合成情境）。
- Python 原上傳影片（32 秒，961 個原始幀）：`--sample-every 6 --full-scan-every 4 --scale .5 --white-threshold .75`，分析 161 幀，輸出 41 手黑白落子；和提供的 `Record_of_moves.csv` **所有 41 手依序相符**，獲勝者黑棋。
- 這是與原程式輸出的一致性測試，不是第三方標註 ground-truth 精度評估。
- C#：目前生成完整原始碼、NuGet 專案與自我測試，但開發環境沒有 .NET SDK，不宣稱已在 Windows 編譯或跑出相同結果。

## 回歸測試計畫
- Python 14 項 `pytest`（核心、戰術、校準、合成影片、取消），本次環境全部通過。
- C# `--self-test` 棋型/推薦規則測試。
- Windows 同時跑完兩種版本後，用 `compare_runs.py` 比對顏色、座標與勝負；較深的每幀細節需另外記錄。
- 若做速度比較：同一台 Windows 主機、同一素材、相同執行參數、暖身後至少 5 次、排除冷啟動，並記錄 CPU / 磁碟 / codec。
