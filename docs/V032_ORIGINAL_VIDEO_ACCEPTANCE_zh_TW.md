# GomokuVision V0.3.2 — 原始期末影片本機匯入與棋譜同步

## 目的

V0.3.1 預設 `demo/demo.mp4` 是自製的 9 手合成影片，不是 2025 年期末專題的 961 來源影格影片。因此若按「開始辨識與預測」，會產生 9 手而不是原始 41 手，這不是新版原始影片的驗證結果。

## 本機原始資料如何使用（不必重跑）

1. **先確認原始影片與模板合法授權範圍**。從最初的期末專題 RAR 解壓到本機一個私人資料夾，例如 `D:\GomokuLocalInput`；不要直接放入準備公開的 GitHub 專案。
2. 該資料夾需同時包含 `input.mp4`、`checkerboard_points.csv`、`black.png`、`white.png`，來源都應是**原始專題**，不能混用 `demo` 的模板／校準。
3. 從本次 V0.3.2 ZIP 解壓並啟動 WPF，按左側頂部「**匯入原始專題資料夾（本機私人影片）**」；選取原始資料夾。
4. 程式只會設定上述四個輸入路徑，重新讀取套件內**已保存的 41 手歷史 CSV**，並載入本機影片預覽。它不會重新運行辨識引擎，也不會上傳或複製影片到套件內。
5. 程式檢查本機影片 SHA-256 是否與先前上傳的原始 `input.mp4` 一致，同時檢查已保存的 41 手 CSV；**兩者匹配**才允許棋步拖曳時將影片定位到對應影格。
6. 驗收應顯示**961 來源影格、41 手棋步**，而不是 demo 9 手。按上一手／下一手、點選第 41 手 `L8`，影片定位到來源影格 `949`；可以拖曳影片影格時間軸看棋譜同步。
7. 如果影片不匹配（例如壓縮過、重新編碼），它仍可獨立預覽，但**不會假裝與 41 手歷史棋譜對應**。如需配對此新影片，請另外明確執行「開始辨識與預測」產生一份新的結果。

## 要測新的 Python／C# 真實影片辨識

匯入後在左側引擎選 `Python / OpenCV` 或 `C# / OpenCvSharp`，各自指定**不同結果資料夾**，手動點「開始辨識與預測」。目前使用者在 Windows 已實測的跨引擎 11/11 PASS 是 9 手合成影片；原始 961 幀的 C# 引擎驗收仍需獨立測試。

## 驗收與限制

- Python V0.3.1 核心在此環境已直接使用原始專題影片／CSV／兩張模板，得 961 source frames、161 analyzed frames、41 moves、Black winner，與舊 CSV 41 手一致；這是**相對舊程式輸出的一致性檢查**，不是人工標註的辨識準確率。
- 本修正版目前僅進行 WPF XAML／來源測試；**Windows 上的 V0.3.2 新按鈕與影片同步仍待 GUI 實測**。
- 這次 ZIP **不包含原始第三方影片、擷取的原始棋子模板、姓名與學號的 PDF**，也沒有將這些素材上傳到 GitHub。
